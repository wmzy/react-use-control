# React Use Control

> **One prop per state.** A control is a token that finds or creates the `useState` at the right layer of the tree. Not a store, not a signal — React stays the store.

If you've ever written `value` / `defaultValue` / `onChange` for a wrapper component, this library deletes that boilerplate.

## The Idea

```jsx
const [value, setValue, control] = useControl(0);
```

- The **value and setter** are ordinary React state, created in the first component that calls `useControl`.
- The **control** is a token for that state. Pass it down; children adopt it instead of creating their own.
- Pass a plain value instead → uncontrolled, that value is the default.
- One code path. No `isControlled` branches, no sync effects, no double source.

## What a Control Is Not

- **Not a signal / Jotai atom.** No store, no subscription, no module-level state. The state is a plain `useState` inside the tree, and it dies with its owner component.
- **Not a form adapter.** When a form library owns the state, use that library's API. Controls are for components that *may* own state.

## Core API

| API | Description |
| --- | --- |
| `useControl(control?, initial)` | Returns `[value, setValue, control]` |
| `useThru(control, interceptor)` | Wrap a control with a state/setter transform |
| `isControl(x)` | Type guard for control objects |
| `mapState(fn)` | Transform the value children read |
| `mapSetter(fn)` | Transform values before they reach setState |
| `watch(onChange)` | Side effect on writes |

## Concepts

### Uncontrolled Mode

No control passed — the component manages its own state:

```jsx
function Counter() {
  const [count, setCount] = useControl(null, 0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

### Controlled Mode

Pass a control from a parent to share state:

```jsx
function Parent() {
  const [count, setCount, control] = useControl(null, 0);
  return (
    <>
      <Counter count={control} />
      <button onClick={() => setCount(0)}>Reset</button>
    </>
  );
}
```

### Sibling Sharing

The same control passed to multiple children — they share one state, no Context:

```jsx
function App() {
  const [, , control] = useControl(null, 0);
  return (
    <>
      <Counter count={control} />
      <Counter count={control} />
    </>
  );
}
```

### State Transforms

`useThru` intercepts state flowing through the tree. It never creates state — the child
stays the owner and the trigger; the wrapper contributes only the transform:

```jsx
const doubled = useThru(count, mapSetter(v => v * 2));
```
